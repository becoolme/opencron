# Working in this repository

Guidance for coding agents and for people. [CONTRIBUTING.md](CONTRIBUTING.md) covers setup and the checks to run; this
file adds the rules a change has to follow.

## Editions and branches

- `main` is the open-source edition and is published as `becoolme/opencron`. The hosted edition lives on the `cloud`
  branch in a private repository; it merges `main` and is never merged back.
- Hosted-only code (`apps/api/src/cloud/`, `apps/api/wrangler.cloud.toml`, `packages/stripe-billing`) never appears on
  `main`, and nothing on `main` imports from it. `node scripts/check-editions.mjs` (part of `pnpm test`) enforces this.
- Production identifiers (domains, D1 and KV ids, account ids) belong in `wrangler.cloud.toml` on `cloud`, never in
  `apps/api/wrangler.toml`.

## Code shared with OpenUptime

`packages/kit` and `packages/mcp-rest` are copied from [OpenUptime](https://github.com/becoolme/openuptime) and must stay
identical to it:

- Change them in OpenUptime first, then run `pnpm sync:openuptime` here (it reads `../openuptime`, or
  `OPENUPTIME_DIR`) and commit the package together with `shared-packages.lock.json`.
- `pnpm check:shared` (part of `pnpm test`) fails when a vendored file was edited here.
- Something OpenCron needs from OpenUptime that is still inside its apps (an alert channel, a helper) gets moved into a
  package over there first, then synced here. Do not copy it by hand.

## Runtime

OpenCron deploys to Cloudflare Workers by default. There, script jobs are JavaScript modules run by the Worker Loader
with `nodejs_compat`; there is no Python or shell runtime, and scripts have no outbound network access. An operator
can set `SANDBOX_URL` to a sandbox on their own server (`docker-compose.sandbox.yml`), which then runs Python and Go
jobs; `apps/api/src/sandbox-client.ts` requires HTTPS for it outside a private network.

The Docker deployment (`docker-compose.yml`, `apps/api/src/server.ts`, `apps/sandbox`) adds Node.js, Python and Go,
each run in a fresh container with no network, a read-only root, no capabilities and fixed limits
(`apps/sandbox/src/docker-args.mjs`, tested). The sandbox reaches Docker only through `docker-guard`, which refuses
any container that does not match those flags (`apps/sandbox/src/docker-policy.mjs`, tested). Never loosen either
without a test and an entry in `docs/docker.md`.
The UI offers only what `GET /api/meta` reports for the deployment.

## Other conventions

- **Tests** sit next to the code they cover (`apps/api/test`). A rule that has bitten us gets a test or a check script,
  not a reminder here.
- **Settings** a deployment reads are documented in `docs/deploy.md` and declared in `apps/api/wrangler.toml`.
- **Outbound requests** to user-supplied URLs go through `guardedFetch` from `@openuptime/kit/netguard`, never a bare
  `fetch`.
- **Commits**: an imperative subject that says what the change does, a body that says why when it is not obvious. Do not
  add attribution or "generated by" lines to commit messages or pull request descriptions. Stage files explicitly
  rather than with `git add -A`.
- Never put real credentials, tokens or customer data in the repository, tests or fixtures.
